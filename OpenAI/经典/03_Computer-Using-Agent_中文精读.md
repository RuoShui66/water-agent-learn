# 计算机使用 Agent

- 英文标题：Computer-Using Agent
- 发布日期：2025-01-23
- 类型：经典 / GUI Agent / 模型研究
- [OpenAI 官方原文](https://openai.com/index/computer-using-agent/)

> 本文是中文精读与转述，不是逐句全文翻译。

## 一句话摘要

Computer-Using Agent（CUA）把视觉理解与强化学习得到的推理能力结合起来，通过截图、鼠标和键盘操作图形界面，使 Agent 能处理没有 API 的数字任务；但 GUI 的开放性也让提示注入、误操作和高风险动作成为核心安全问题。

## 它怎样工作

CUA 观察屏幕截图，推理下一步，再输出鼠标移动、点击、滚动或键盘输入等动作。环境执行动作并返回新截图，模型据此继续循环。它不需要针对每个网站读取 DOM 或编写专用 API，因此可以把人类界面当作通用接口。

文章介绍的模型把 GPT-4o 的视觉能力与强化学习训练的推理结合起来。训练目标不只是识别按钮，而是完成多步 GUI 任务：处理弹窗、修正错误、在页面状态变化后重新规划。

## 为什么 GUI Agent 有价值

- 大量企业和个人工作流仍没有稳定 API；
- 即使有 API，覆盖面也可能不完整或接入成本高；
- 视觉界面是一种跨应用的共同协议；
- 同一 Agent 可以在不同网站和传统应用间迁移。

## 主要限制

界面操作比结构化 API 更慢、更脆弱。页面布局变化、延迟、模态窗口和视觉歧义都会造成错误。复杂操作的长链条还会让单步小误差累积。因此 CUA 更适合作为 API 不可用时的补充，而不是默认替换所有确定性集成。

## 安全设计

计算机使用 Agent 能真正改变外部世界，风险显著高于文本回答。官方文章强调：

- 登录信息等敏感输入可由用户接管；
- 购买、发送、提交等高影响动作前要求确认；
- 对网站中的恶意指令和提示注入进行防护；
- 限制敏感或高风险任务；
- 让用户可以观察、中断和恢复控制。

## 可直接带走的工程原则

- 优先级通常应是：稳定 API > 结构化浏览器接口 > 纯视觉 GUI。
- 每个动作后验证环境状态，不要只根据“点击已发出”判断成功。
- 把导航、填写与最终提交分开；最终不可逆动作单独确认。
- 页面内容属于不可信输入，不能覆盖系统指令或权限策略。
- 为任务设置时间、步数、费用和作用域上限。
- 保存截图、动作和结果，支持事后审计与失败重放。

## 为什么是经典

CUA 是 Agent 从“调用开发者预先定义的工具”走向“操作任意现有软件”的关键一步，也提前暴露了后来所有 computer-use Agent 都必须面对的安全与可靠性问题。
