## 一句话摘要

当 Agent 负责写几乎所有代码时，人类工程师的主要工作从“亲手编码”变成设计环境、表达意图、维护架构约束和反馈回路；代码库是否对 Agent 可读、可测试、可导航，直接决定产出质量。

## 背景

OpenAI 团队用 Codex 从空仓库构建一个内部产品，文章称所有应用代码、测试、CI、文档、可观测性和内部工具都由 Codex 生成，规模达到约百万行，并估计开发速度约为手写方式的十倍。数字是特定实验的官方估计，更重要的是实验暴露出的工作方式变化。

## 核心内容

### 1. Humans steer, agents execute

人类不再逐行实现，而是描述任务、给出验收标准、让 Agent 创建变更并审查结果。稀缺资源从键盘输入速度变成人类判断力与注意力。

### 2. Agent legibility 成为代码质量维度

面向新人友好的仓库通常也更适合 Agent：结构清晰、命名一致、领域概念可从代码和文档追踪、构建与测试命令稳定。隐含在某个人脑中的知识必须进入仓库，仓库成为系统记录。

### 3. 约束要机械化

“请保持架构整洁”太抽象。更可靠的做法是把边界编码成依赖规则、lint、类型、测试、生成器和 CI 检查。Agent 可以高速生成代码，也会高速放大没有被自动阻止的坏模式。

### 4. 高吞吐改变合并哲学

Agent 让变更和修复都更便宜，因此团队可以偏向较小、可回退、可观察的增量，而不是等待一个人工精雕的大补丁。前提是测试、监控和回滚同样自动化。

### 5. 熵需要主动清理

即使每个局部改动都“能工作”，大量改动仍会积累重复抽象、过时文档和不一致模式。需要持续的 garbage collection：让 Agent 定期发现并清理结构性债务。

## 可直接带走的工程原则

- 在根目录写清唯一的构建、测试、lint 和验证入口。
- 把领域规则放入代码、schema 与测试，不要只放在聊天或会议纪要中。
- 用架构测试限制跨层依赖，用生成器固定重复结构。
- 为每个任务提供可执行验收条件，而不只描述功能意图。
- 将文档陈旧、重复代码、未使用依赖和架构偏移纳入周期性 Agent 维护任务。
- 审查重点从“每一行怎么写”上移到“系统边界、风险与证据是否充分”。

## 为什么值得读

这篇文章讨论的不只是 Codex，而是软件工程团队在 Agent 吞吐提高后怎样重新设计整个生产系统。它与 Anthropic 的长任务 harness 文章互补：Anthropic 更关注一次长运行内部怎样稳定，OpenAI 更关注整个仓库和团队怎样变成 Agent 的外部 harness。
