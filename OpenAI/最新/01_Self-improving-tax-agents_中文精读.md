# 用 Codex 构建会自我改进的税务 Agent

- 英文标题：Building self-improving tax agents with Codex
- 发布日期：2026-05-27
- 类型：最新 / 生产实践 / 评测闭环
- [OpenAI 官方原文](https://openai.com/index/building-self-improving-tax-agents-with-codex/)

> 本文是中文精读与转述，不是逐句全文翻译。

## 一句话摘要

真正可控的“自我改进”不是让 Agent 随意重写自己，而是把专家在生产中的纠错保存为结构化证据，再转成 eval，由 Codex 在明确的质量门槛上持续修改和验证系统。

## 文章在解决什么问题

实验室里的测试无法覆盖生产环境的脏数据、例外流程和专业判断。传统改进链条是：用户发现错误，工程师复现，人工修改提示词或代码，再祈祷没有引入回归。这个链条慢，而且大量专家反馈在操作完成后就丢失了。

OpenAI 与 Thrive Holdings、Crete 会计事务所网络一起构建 Tax AI。文章给出的关键不是某个税务提示词，而是一套可以迁移到其他专业领域的三段式闭环：

1. 专业人员的纠正暴露真实失败；
2. 产品保存从输入、推理过程、工具操作到最终结果的 production trace；
3. 失败被转成针对性的 eval 和待攀登指标，Codex 据此修改实现，并在部署前验证。

## 核心内容

### 1. 先把反馈变成“可解释信号”

一个数字被会计师改掉，不一定说明 OCR 错了；也可能是字段映射、产品能力缺失、跨文件对账或正常工作流噪声。系统必须保留足够上下文，才能判断错误属于哪一层。否则所谓反馈只是模糊的“答案不对”。

### 2. Trace 是连接生产与评测的桥

完整 trace 让工程系统知道 Agent 看到了什么、执行了什么、在哪一步偏离。高价值失败样本随后进入能力评测；已经稳定通过的能力进入回归套件。这样每次修改都有可量化目标，也有防止旧能力退化的保护网。

### 3. 专家负责定义正确，Agent 负责扩大工程吞吐

税务知识仍来自一线会计师。Codex 的价值是把经过确认的失败批量转化为代码、抽取规则、测试、评测用例和新能力，而不是取代领域专家决定税务事实。

### 4. 复用的不是单个修复，而是抽象

文章以出租物业相关表格为例：达到较高 precision/recall 的早期阶段需要约六周，但产生的评审产物、eval 约定和实现模式随后可复用于 Schedule C、Schedule A 等相邻流程。系统改进开始具有复利。

## 官方文章报告的结果

- 试点税季处理约 7,000 份报税表；
- 对更复杂表格的完成度持续提高；
- 一个案例中，高级会计师的报税准备投入从上一年的约 180 小时降到约 15 小时；
- 出租物业能力的早期建设形成了可迁移到其他税务日程表的工程资产。

这些数字来自 OpenAI 官方案例，应理解为特定试点环境的结果，不宜直接外推到所有税务系统。

## 可直接带走的工程原则

- 在 UI 中显式记录用户修正前值、修正后值、来源文档和相关 trace。
- 把“能力评测”和“回归评测”分开：前者要有提升空间，后者应接近全通过。
- Agent 可以生成修复，但合入标准必须由确定性测试、领域规则和专家抽检共同决定。
- 先设计反馈数据模型，再谈自我改进；没有结构化信号，只会自动放大噪声。
- 对高风险专业领域保留可追溯证据与人工最终责任。

## 为什么值得读

这篇文章把“self-improving agent”从营销词还原成可审计的软件工程循环。它与 Anthropic《Demystifying evals for AI agents》配合阅读最好：后者给出评测方法论，本文给出生产闭环实例。
