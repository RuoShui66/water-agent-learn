## 五条跨篇主线

把九篇串起来看，会发现它们在回答同一组问题：

1. **「做完」怎么定义** —— `03` 的 default-FAIL 契约 → `04` 的条件四件套 → `08` 的强目标 vs 弱目标。三家措辞不同，结构完全同构：**可度量终态 + 明示验证方式 + 约束 + 上限**。
2. **谁来判「做完」** —— `03` 的 fresh-context evaluator → `04` 的 small fast model → `01` 的 Outcomes grader。共识是**判定者必须有独立上下文**；唯一的反对声在 `09`（专职 QA 智能体收敛失败）。
3. **状态放哪** —— `03` 的 `PROGRESS.md` + git → `07` 的 brain/hands/session → `08` 的 memory vault。共识是**外置到可 diff、可评审的文件**。
4. **脚手架该删还是该加** —— `05` 正反两条数字 + `06` 的「不缩小，只是转移」+ `03` 的逐个注释消融法。结论是**行为管教层该删、基础设施层要加**。
5. **成本谁来兜** —— `02` 的「并行必须挣回协调成本」+ `07` 的断路器 + `09` 的单次数百美元报告。三者指向同一句：**多智能体不是默认选项**。
