## 一句话讲明白

**Anthropic 把「Agent 怎么记住东西」的答案定死在了文件系统上——记忆不是向量库、不是专用存储，就是挂载的文件目录，让 Claude 用它已经会的 bash 和代码执行去读写。在这之上叠了三件事：Dreaming（离线复盘把记忆重新整理）、Outcomes（把成功判据交给独立评分器）、多智能体编排（主 Agent 派发给专精 Agent，共享存储 + 全链路追踪）。**

## 第一部分：内置记忆（2026-04-23）

### 1. ⭐ 核心架构：记忆就是文件系统

**记忆层直接挂载到文件系统上**，这样 Claude 可以复用它**已经掌握的 bash 和代码执行能力**去操作记忆。

> **这个设计决策才是重点，不是功能本身。** 它是 [B16 harness 三模式](B16_harnessing-claudes-intelligence_学习笔记.md) 里「模式 1：靠模型别靠 harness」的直接体现——不给 Claude 造一套新的记忆 API，而是把记忆表达成它已经会用的东西（文件）。
>
> **面试可用**：被问「记忆系统怎么设计」，Anthropic 官方答案是**别造专用存储层，挂文件系统**。理由是模型对文件操作的熟练度是免费的、且随模型升级自动提升；专用 API 的熟练度要靠提示词教，且写死在设计那天。

### 2. 存储与访问

| 机制 | 说明 |
|---|---|
| **文件形态存储** | 记忆存为文件，开发者可通过 API **导出**和程序化管理 |
| ⭐ **作用域权限（scoped permissions）** | 差异化访问：例如**组织级只读**存储 + **按用户读写**存储 |
| **并发安全** | 多个 Agent 可以同时对同一个存储工作而**不互相覆盖** |

**作用域权限这个设计值得记**：它解决了「团队共享知识 vs 个人私有记忆」的冲突——组织级沉淀设为只读防止个体污染，个人层可写。这是记忆系统上生产必须回答的问题。

### 3. 追踪与控制（企业级要求）

| 能力 | 说明 |
|---|---|
| **审计日志** | 记录**哪个 Agent、哪个会话**创建了每条记忆 |
| **回滚（rollback）** | 可回退到早期版本 |
| **内容脱敏（redaction）** | 从历史中移除敏感信息 |
| **可观测性** | 更新以 session event 的形式出现在 Claude Console |

> **「记忆需要审计和回滚」是很多人做记忆系统时想不到的**。一旦 Agent 把错误的结论写进长期记忆，它会持续污染后续所有会话——**没有回滚就没有纠错路径**。面试提到这点会很加分。

### 4. 模型能力与记忆质量的耦合

官方说法：记忆层针对长时程 Agent 的内部基准做了优化，且**更新的 Claude 模型能存下更全面、组织更好的记忆，并且对「这个任务该记什么」更有分辨力**。

> 与 [B16](B16_harnessing-claudes-intelligence_学习笔记.md) 的宝可梦案例完全呼应：Sonnet 3.5 在 14,000 步时留下 31 个关于毛毛虫的重复文件，Opus 4.6 留下 10 个组织良好的战术笔记。**记忆质量的瓶颈是判断力，不是存储机制。**

### 5. 客户实测数据（面试弹药）

| 客户 | 结果 |
|---|---|
| **Rakuten（乐天）** | Agent 首轮错误率**降低 97%** |
| **Wisedocs** | 通过跨会话记忆，验证流程**加速 30%** |

## 第二部分：三个新特性（2026-05-19，Code w/ Claude 发布）

### 1. ⭐ Dreaming（做梦）—— research preview

**做什么**：一个**定时进程**，回顾 Agent 的会话和记忆存储，提取模式，帮 Agent 随时间自我改进。

**它能看到什么（单个 Agent 看不到的）**：
- **反复出现的错误**
- Agent 们**收敛到的工作流**
- **团队内共享的偏好**

**关键机制**：Dreaming 会**重构记忆结构**，以在记忆演化过程中维持信噪比。

> ⭐ **这是 2026 年 Anthropic 记忆架构最大的概念增量，也是最值得你研究的一块**。
>
> **核心洞察**：记忆系统的敌人不是容量，是**信噪比随时间衰减**。在线写入的记忆是局部最优的——每条单独看都合理，累积起来会重复、矛盾、过期。Dreaming 的解法是**把「整理」和「记录」分离到不同时间尺度**：在线只管记，离线批量重构。
>
> 这个「在线记录 / 离线整理」的双时间尺度设计，是可以直接搬到自己项目里的架构决策。名字借了人类睡眠中记忆巩固的隐喻，但工程本质是**定期的批量再索引 + 去重 + 抽象提升**。

### 2. Outcomes（结果）—— public beta

**做什么**：开发者通过**评分标准（rubric）** 定义成功判据，一个**独立的评分器（grader）** 在**自己的上下文窗口里**评估 Agent 输出。

**关键设计**：评分器在独立上下文里跑，是为了**不被 Agent 的推理过程影响**。工作不达标时，评分器**指出具体要改什么**，Agent 再来一轮。

⭐ **实测**：任务成功率最高提升 **10 个百分点**；具体到文件生成——**docx +8.4%，pptx +10.1%**。

> **「独立上下文窗口」是这里的技术要点**。如果评分器能看到生成器的推理过程，它会被那个推理说服（「它是这么想的，那好像有道理」）——这正是 `21_harness-design-long-running-apps` 里说的「模型天生对模型生成的东西手下留情」。**隔离上下文是对抗这种偏袒的结构性手段。**
>
> 这也是 [B18](B18_multi-agent-coordination-patterns_学习笔记.md) generator-verifier 模式的产品化，且回应了那篇指出的弱点（标准含糊会给虚假安全感）——Outcomes 强制你先写出 rubric。

### 3. Multiagent Orchestration（多智能体编排）—— public beta

**做什么**：主 Agent（lead agent）把复杂工作拆开，委派给**有各自模型、提示词、工具**的专精 Agent。

| 机制 | 说明 |
|---|---|
| **并行 + 共享存储** | 专精 Agent 并行工作在共享存储上 |
| **贡献回主上下文** | 专精 Agent 的产出汇入主 Agent 的整体上下文 |
| ⭐ **持久化事件** | **每个 Agent 都记得自己做过什么**，因此支持**工作流中途插入检查（mid-workflow check-ins）** |
| **全链路追踪** | Claude Console 里可看到**哪个 Agent 做了哪个动作、以及它的推理** |

> 对照 [B18](B18_multi-agent-coordination-patterns_学习笔记.md)：这是 **orchestrator-subagent + shared state 的混合产品化**。它专门补掉了纯 orchestrator-subagent 的两个弱点——用共享存储绕开**信息瓶颈**，用持久化事件解决子 Agent「做完即忘」的问题。

## 三个特性的关系（这样串起来讲最清楚）

```
        Multiagent Orchestration   ← 空间维度：谁来干（并行分工）
                  │
        ┌─────────┴─────────┐
        ↓                   ↓
    Outcomes            Memory        ← 质量维度：干得对不对 / 记住什么
   （独立评分器）      （文件系统）
                            ↓
                       Dreaming       ← 时间维度：离线重构，对抗信噪比衰减
```

- **Memory** 解决「跨会话保留」
- **Dreaming** 解决「保留久了会烂」
- **Outcomes** 解决「怎么知道做对了」
- **Multiagent Orchestration** 解决「怎么并行且不丢信息」

## 面试怎么用（重点：记忆系统设计）

**被问「你的记忆系统怎么设计的 / 你怎么看记忆系统」**：

1. **存储形态**：Anthropic 官方选择是**挂文件系统而不是造专用存储**——理由是复用模型已有的 bash/代码能力，熟练度免费且随模型升级自动提升。
2. **权限模型**：作用域权限（组织级只读 + 用户级读写）解决团队沉淀与个人记忆的污染冲突。
3. **可运维性**：审计日志（哪个 Agent 哪个会话写的）+ 回滚 + 脱敏。**错误记忆会持续污染后续所有会话，没有回滚就没有纠错路径**——这条最能显出你想过生产问题。
4. **⭐ 时间维度**：记忆系统真正的敌人是**信噪比随时间衰减**，不是容量。Dreaming 的解法是把「记录」和「整理」分到两个时间尺度——在线只管记，离线批量重构去重、提升抽象层次。
5. **能力耦合**：引宝可梦对比——同样的记忆机制，弱模型写成 31 个重复流水账卡在第二个城镇，强模型写成 10 个战术笔记拿 3 个徽章。**记忆质量的瓶颈是判断力，所以设计时要给判断力留空间，不要把「存什么」写死成规则。**

**被问「多 Agent 怎么避免信息丢失」**：
Multiagent Orchestration 的两个机制——**共享存储**绕开编排者信息瓶颈，**持久化事件**让每个 Agent 记得自己做过什么并支持中途插入检查。
