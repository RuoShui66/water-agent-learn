## 跨篇主线（面试时把这条讲出来最加分）

Anthropic 全套材料其实只有**一个元方法论**，在不同层面重复出现：

> **Harness 的每个组件、提示词的每条规则，都是在补当前模型的某个能力缺口。缺口随模型升级消失，补丁却留在原地成为束缚。所以要定期回头问：我还能停掉什么？**

它在五个层面的具体形态：

| 层面 | 出处 | 具体动作 |
|---|---|---|
| **Harness 组件** | [B16](B16_harnessing-claudes-intelligence_学习笔记.md) · `Engineering 21` | 新模型上线后拆脚手架，一次只拆一个 |
| **提示词** | [B26](B26_new-rules-of-context-engineering_学习笔记.md) | unhobbling；Claude Code 系统提示词删掉 80%+ |
| **工具设计** | [B16](B16_harnessing-claudes-intelligence_学习笔记.md) 3B · [B19](B19_seeing-like-an-agent_逐句对照.md) | 专用工具会削弱模型杠杆；TodoWrite→Task 即「工具成束缚后删掉」的实例 |
| **记忆机制** | [B20](B20_managed-agents-memory-and-new-features_学习笔记.md) | 别造专用存储层，挂文件系统复用模型已有能力 |
| **Skills** | [B13](B13_improving-skill-creator_逐句对照.md) | 基模不带 skill 也通过 evals = skill 该退役——「还能停掉什么」的评测化 |

以及一条贯穿的**验证原则**：

> **能确定性验证就别用模型评判**（[B05](B05_building-agents-with-the-claude-agent-sdk_学习笔记.md)）→ 展开为**「验证机械化、审查对抗化」**（[B25](B25_ai-code-migration_学习笔记.md)）→ 产品化为 **Outcomes 的独立上下文评分器**（[B20](B20_managed-agents-memory-and-new-features_学习笔记.md)）→ 团队化为 **Doer-Verifier 与「所有交给 Agent 的工作必须可验证」**（[B24](B24_building-effective-human-agent-teams_逐句对照.md)）。
